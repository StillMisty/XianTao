# 命令系统 详细设计

行为契约见同目录 spec.md；本文档为详细设计参考。

## 1. 总体说明

命令系统把 QQ 群消息路由到 22 个命令组（监听器类）、共 71 条指令；另有 20 个帮助分组（命令处理器），面向玩家提供「帮助」三层结构与纠错。福地经营、秘境探索、商铺买卖、宗门事务均通过对应 NPC 的**自然语言对话**完成。

本文档分三部分：玩家视角的指令参考（第 2 节，修正后与代码一致）、调度与匹配语义（第 3 节）、指令清单与帮助元数据（第 4、5 节）。

## 3. 调度与匹配语义

### 3.1 模板语法（`@Command`）

模板语义与旧 SimBot `@Filter` 逐条对齐：

- `{{name}}` → 命名捕获组 `(?<name>.+)`（贪婪，至少 1 字符）
- `{{name,正则}}` → `(?<name>正则)`，参数正则内允许嵌套花括号
- 模板不含 `{{` 时整体按字面量（`Pattern.quote`）匹配
- 模板含占位符时，占位符之外的文本按原样作为正则（如 `\s*`、`(?!方)` 负向前瞻）
- 匹配使用 `Matcher.matches()`（**全匹配**，不是前缀/子串）
- 消息在匹配前先 `strip()` 去除首尾空白
- 参数名必须是字母开头的字母数字串；重复参数名、缺少 `}}`、空正则、空模板都会在启动时抛异常

### 3.2 注册与匹配顺序

- 启动时扫描所有 `@CommandGroup` bean 的 `@Command` 方法，编译模板并校验参数绑定；重复模板、非 void 返回、非法参数类型、`@Arg` 无对应占位符、`@RequireGm` 缺 `@RequireAuth` 均导致启动失败。
- 匹配顺序：**无占位符的字面量命令优先于参数化命令**，同级按模板字典序（`CommandRegistry.matchOrder()`）。这保证「锻造列表」不被「锻造 {{input}}」遮蔽，「排行榜 灵石」不被「排行榜」混淆。
- `CommandShadowingTest` 用与运行期一致的顺序校验每条命令的样例消息不会被其它模板抢先命中。

### 3.3 执行管线

每条 QQ 消息一条虚拟线程；匹配成功后进入 `PerKeySerialExecutor`，键为 `平台:openId`：

1. **匹配**：按 3.2 的顺序找到第一条全匹配模板；提取命名参数。
2. **认证**：`@RequireAuth` 指令校验平台绑定；未注册时回复「输入「我要修仙 [道号]」进入仙途吧！」并终止。「我要修仙」本身不要求认证。
3. **GM**：`@RequireGm` 指令在认证通过后校验 GM 标记；非 GM 回复「你不是 GM，无法执行 GM 指令」并终止。
4. **执行**：认证通过后把 userId 绑定到 `ScopedValue` 再调用处理器。
5. **串行**：同一玩家（`平台:openId`）的命令严格按到达顺序串行执行，跨玩家并行（避免双击/连点/重复注册竞态）。

### 3.4 缺参兜底

模板编译时提取「字面前缀」：第一个占位符之前的命令名，去掉结尾的 `\s*`/`\s+` 与负向前瞻。例如：

| 模板 | 字面前缀 |
|------|----------|
| `前往\s*{{mapName}}` | `前往` |
| `使用\s*{{itemName,\S+}}` | `使用` |
| `护道(?!解除\|查询)\s*{{nickname,\S+}}` | `护道` |
| `参与事件\s*{{eventId,\d+}}` | `参与事件` |
| `GM给灵石\s*{{nickname}}\s+{{amount}}` | `GM给灵石` |
| `锻造\s*{{input}}` | `锻造` |

当整条消息恰好等于某个参数化命令的字面前缀时，回复：

```
「前往」还需要补充内容，输入「帮助 前往」查看用法
```

纯字面量命令没有前缀兜底（它们能直接匹配）。除统一兜底外，个别处理器还有内部防御（如「法决装载」缺参返回用法示例、「参与事件」非数字返回格式错误、GM 数量/等级解析失败返回「数量格式错误」等）。

### 3.5 未匹配与异常兜底

- 既不匹配任何模板、也不命中字面前缀的消息**静默忽略**（不回复）。
- 处理器抛异常或返回空文本时统一回复「系统繁忙，请稍后再试」；`ReplyHelper` 对 null/空白回复做 sanitize。
- 业务失败（`BusinessException`）以 `ErrorCode` 文案回复；`ServiceResult.Failure` 以消息文本回复。

## 5. 帮助系统

### 5.1 三层结构

1. **总览**：「帮助」列出全部帮助分组（`groupName — groupSummary`），并提示「输入「帮助 [子系统]」查看详细玩法，如「帮助 修炼」」。
2. **分组详情**：「帮助 分组名」展示分组说明（`groupDescription`）与组内每条指令（触发词 — 说明），并提示「输入「帮助 [命令]」查看单条命令用法」。
3. **指令详情**：「帮助 指令触发词」展示指令说明与「用法：usage」。

### 5.2 搜索与纠错

「帮助 X」的解析顺序：分组名精确匹配 → 触发词精确匹配 → 触发词/描述包含搜索：

- 命中 1 条 → 直接展示指令详情
- 命中多条 → 展示「搜索 X 找到以下命令」列表
- 无命中 → 「未找到命令或子系统：X」；若有近似候选，追加「你是不是想找：…」

## 迁移评估：设计取舍

> 原设计文档与实现的差异评估。A 实现现状（文档已按代码修正）；B 保留代码设计（更合乎玩法）；C 按设计修正（设计意图更优，条目标注已修/待修）；D 未实现（待办）；E 缺陷修复。

### A. 实现现状（文档已修正）

- **`使用` 双模板**：`使用 {{物品}}` 与 `使用 {{物品}} {{参数}}` 两条模板，带参数用法不会命中无参模板（行为等价，仅调度结构不同）。
- **`宗门创建` 理念可省略**：带道统描述与不带两条模板。
- **`查看` 目标范围**：实际支持装备 / 怪物 / 物品 / 玩家档案。
- **参与事件编号**：模板要求 `\d+`，非数字输入不会命中；处理器内的空参 / 非数字兜底为防御代码，正常链路不可达。
- **GM 指令补全**：文档已补上 8 条 GM 指令（GM帮助 / 给灵石 / 给修为 / 治疗 / 复活 / 等级 / 传送 / 给物品）；GM 分组不出现在「帮助」总览，只能通过「GM帮助」查看。
- **命令面声明**：文档已按代码补全为 22 个命令组 / 71 条，覆盖裸「秘灵」与 GM 指令。

### B. 保留代码设计

- **`选` 只接受单字母 A–Z**：与选择事件按钮（发送「选 A」）一致，单字母作答无歧义、不区分大小写；非字母返回「无效的选择…」。
- **裸 `秘灵` 返回用法引导**：无内容时给出「秘灵 你说的话」用法与示例，优于静默忽略。
- **`卸下` 支持部位名 / 物品名 / 编号**：三种输入都能卸下装备，比只支持部位名更少挫败。
- **未注册引导只对需认证指令生效，其余文本静默**：群聊场景不对无关消息刷屏，只有明确的指令意图才引导注册。
