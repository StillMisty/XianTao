# game-events Specification

## Purpose
定义异步事件系统的行为契约：后台完成的状态变化如何作为可投递事件在任意回复后呈现给玩家、事件的分节与模板渲染、旅行/历练/悬赏/状态恢复等场景的触发与产出、隐藏事件与选择事件的规则、事件配置驱动、事务一致性与保留清理。详细数据模型与实现细节见 `openspec/specs/game-events/design.md`。

## Requirements

### Requirement: 未投递事件投递

玩家发出任意命令后，系统 MUST 在回复尾部追加该玩家全部未投递事件（按发生时间排序），并 MUST 在回复发送成功后将这些事件标记为已投递；发送失败时 MUST 不标记，保证下次回复重新投递且事件不丢失。

#### Scenario: 回复附带未投递事件

- **WHEN** 玩家在旅行到达后发出任意命令
- **THEN** 回复正文之后追加到达叙事，且该事件在发送成功后不再重复出现

#### Scenario: 发送失败不丢失

- **WHEN** 回复发送失败
- **THEN** 事件保持未投递，下次回复继续展示

### Requirement: 事件分节与模板渲染

通知 MUST 按事件大类分节：旅途见闻、历练收获、悬赏完成、突破、世界事件、宗门动态、秘境探索、秘境结算、初入仙途等节标题包裹事件；气血恢复、濒死恢复、每日运势等 MUST 以纯文本提示呈现。事件正文 MUST 由随事件存储的叙事模板与参数渲染，模板中未提供参数的占位符 MUST 渲染为「？」，不得暴露内部变量名。

#### Scenario: 同节合并

- **WHEN** 玩家有多条同类未投递事件
- **THEN** 这些事件归入同一节标题下依次展示

#### Scenario: 占位符兜底

- **WHEN** 某事件模板中的占位符没有对应参数
- **THEN** 该占位符展示为「？」

### Requirement: 旅行到达自动结算

旅行 MUST 在到达时间后的下一次状态加载时自动结算：更新所在地图、清空活动状态，并 MUST 产出到达叙事、以基础 30%（按当日命运修正）概率尝试触发一个子事件、检查隐藏事件。无路径的异常旅行 MUST 被安全清除且不卡死玩家。

#### Scenario: 到达自动完成

- **WHEN** 玩家旅行时间已过并再次与游戏交互
- **THEN** 玩家到达目的地，回复追加到达叙事与可能的旅途见闻

#### Scenario: 旅途无额外事件

- **WHEN** 旅行到达但子事件未触发
- **THEN** 仅产出到达叙事，不产出额外事件

### Requirement: 历练结算与中断

历练 MUST 由玩家主动结算（另有每 60 分钟的中途结算推送）；结算时 MUST 对未结算时长执行遇怪与子事件的统一循环，产出历练收获叙事。若战斗导致气血归零，角色 MUST 进入濒死、历练 MUST 中断：结算到死亡点为止的收益、丢弃剩余时间，并 MUST 产出历练中断事件。单次历练过短（≤5 分钟）MUST 无收获。

#### Scenario: 主动结算

- **WHEN** 玩家发送「历练结算」
- **THEN** 系统结算未处理时长，产出历练收获叙事与战斗统计

#### Scenario: 战斗中濒死中断

- **WHEN** 历练中战斗导致气血归零
- **THEN** 历练中断，结算至死亡点，回复追加历练中断提示

#### Scenario: 中途自动结算

- **WHEN** 玩家持续历练满 60 分钟未结算
- **THEN** 系统在下次加载时自动结算该时段并推送历练事件

### Requirement: 悬赏领奖与子事件调节

悬赏 MUST 同时至多进行一个；时长未满时 MUST 拒绝领奖并提示剩余时间。领奖时 MUST 尝试抽取一个悬赏子事件，子事件 MUST 通过上下文调节主奖励（如灵石倍率）而非产出独立奖励；随后 MUST 产出包含实际所得奖励的完成叙事。

#### Scenario: 时长未满

- **WHEN** 玩家在悬赏时长未满时发送「悬赏结算」
- **THEN** 系统拒绝并提示剩余时间

#### Scenario: 领奖调节奖励

- **WHEN** 玩家在时长满后领奖且抽中减益/增益子事件
- **THEN** 实际发放的主奖励相应减少/增加，完成叙事展示调整后的奖励

### Requirement: 状态自动恢复通知

空闲状态下的气血自然恢复 MUST 按固定周期结算，完全恢复时 MUST 产出气血恢复通知；濒死状态超过 30 分钟 MUST 自动恢复约五分之一最大气血并产出恢复通知。

#### Scenario: 气血回满

- **WHEN** 空闲玩家在多次交互后气血自然恢复到上限
- **THEN** 回复追加气血完全恢复提示

#### Scenario: 濒死超时恢复

- **WHEN** 玩家濒死超过 30 分钟
- **THEN** 角色恢复部分气血并产出恢复叙事

### Requirement: 隐藏事件

隐藏事件 MUST 在满足触发条件（持有指定法决、持有指定物品、属性达到阈值，或完成指定前置隐藏事件）且该玩家在该活动该归属下未完成过该事件时触发；触发后 MUST 写入唯一完成记录、执行专属效果并产出专属叙事，之后同一玩家 MUST 不再重复触发。隐藏事件 MUST 在旅行到达、历练结算、悬赏领奖等对应时机检查。

#### Scenario: 条件满足首次触发

- **WHEN** 玩家满足某隐藏事件条件且从未完成过
- **THEN** 事件触发，获得专属奖励与叙事，并记录完成

#### Scenario: 重复经过不再触发

- **WHEN** 已触发过该隐藏事件的玩家再次满足条件
- **THEN** 事件不再触发，仅走普通流程

### Requirement: 选择事件

选择事件触发后 MUST 保持未投递状态，在玩家作出选择前 MUST 在每次回复中重新展示选项（并尽可能附带按钮，点击等价于发送选择指令）。玩家发送「选 [选项]」且选项合法时 MUST 执行该选项效果、标记事件已投递并回复选择结果；选项非法或当前无待选事件时 MUST 给出明确提示。

#### Scenario: 展示与选择

- **WHEN** 旅行中触发选择事件后玩家发送「选 A」
- **THEN** 执行 A 选项效果，事件不再展示，回复选择结果与效果摘要

#### Scenario: 非法选项

- **WHEN** 玩家选择不存在的选项
- **THEN** 系统提示无效选择并列出可用选项

### Requirement: 子事件效果

子事件效果 MUST 由配置驱动并覆盖以下类型：修为（固定/百分比）、气血（百分比/固定扣减与回复）、物品（指定物品、随机物品池、地图特产、装备）、灵石（增加/扣除）、悬赏奖励倍率与纯叙事。事件 MUST 支持按概率分支选择一组效果。叙事模板参数 MUST 由效果执行结果填充。

#### Scenario: 复合效果

- **WHEN** 子事件配置为同时加物与扣血
- **THEN** 物品入包、气血扣减，叙事展示对应结果

#### Scenario: 概率分支

- **WHEN** 子事件配置了互斥概率分支
- **THEN** 每次触发按概率选中一个分支并只执行该分支效果

### Requirement: 事件配置驱动

子事件与隐藏事件的类型、权重、效果参数与触发条件 MUST 由数据配置定义；新增或调整事件 MUST 无需修改代码即可生效，同一事件 code 的不同参数变体 MUST 可独立配置与抽取。

#### Scenario: 新增事件仅配置

- **WHEN** 运营新增一条子事件配置（类型、权重、效果）
- **THEN** 该事件无需代码变更即可参与随机抽取

### Requirement: 事件事务一致性

事件的写入 MUST 与产生它的业务状态变更在同一事务内完成，保证玩家不会遇到「状态已改变但没有任何通知」的情况；投递标记 MUST 在回复发送成功之后独立执行。

#### Scenario: 事务内写入

- **WHEN** 旅行到达结算成功
- **THEN** 位置变更与到达事件同时生效，不会出现只有其一的情况

#### Scenario: 投递后才标记

- **WHEN** 通知已渲染但发送失败
- **THEN** 事件仍为未投递，不因业务事务提交而丢失

### Requirement: 事件保留与清理

已投递事件 MUST 在保留 7 天后由定时任务清理；未投递事件 MUST 不参与清理，直到成功投递后重新计时。

#### Scenario: 到期清理

- **WHEN** 事件投递成功已超过 7 天
- **THEN** 定时清理删除该事件

#### Scenario: 未投递不清理

- **WHEN** 事件因发送失败长期未投递
- **THEN** 该事件不会被清理，仍会在后续回复中展示
