# bounty Specification

## Purpose
定义悬赏的行为契约：悬赏查看（状态/列表）、每日悬赏榜、接取门槛与状态流转、奖励预确定与发放、进度与时间门槛、结算支线事件、放弃与唯一悬赏。奖励池配置、种子与发放实现细节见同目录 design.md。

## Requirements

### Requirement: 悬赏查看

「悬赏」MUST 在玩家有进行中悬赏时显示其状态（名称、描述、进度、预计奖励与后续操作提示），否则显示当前地图可接取的悬赏列表。进行中悬赏的配置缺失时 MUST 降级为列表展示而非报错。

#### Scenario: 有进行中悬赏

- **WHEN** 玩家在悬赏进行中输入「悬赏」
- **THEN** 回复展示悬赏名、描述、已过/总时长、剩余时间（或已可结算）与预计奖励

#### Scenario: 无进行中悬赏

- **WHEN** 空闲玩家输入「悬赏」
- **THEN** 回复展示当前地图可用悬赏列表

### Requirement: 每日悬赏榜

悬赏列表 MUST 只包含当前地图的悬赏，MUST 过滤掉等级要求高于玩家的悬赏，MUST 排除玩家已完成的唯一悬赏，并 MUST 按每日固定结果随机选取 3~4 条（不超过可用条数）。每条 MUST 展示编号、名称、耗时、描述、推荐境界与奖励预览。

#### Scenario: 列表随地图变化

- **WHEN** 玩家在不同地图查看悬赏
- **THEN** 只看到该地图的悬赏

#### Scenario: 等级过滤

- **WHEN** 玩家等级低于某悬赏要求
- **THEN** 该悬赏不出现在列表中

#### Scenario: 同日结果固定

- **WHEN** 同一玩家在同一天重复查看同一地图的悬赏
- **THEN** 列表内容保持一致

### Requirement: 接取悬赏

「悬赏接取 [编号]」MUST 要求玩家处于空闲状态、编号合法、悬赏存在、悬赏属于当前地图且玩家等级达标；唯一悬赏已完成时 MUST 拒绝。接取成功后 MUST 将玩家置为悬赏状态并回复悬赏名与预计完成时长。任何校验失败 MUST 返回明确错误文案且状态不变。

#### Scenario: 成功接取

- **WHEN** 空闲玩家接取当前地图且等级达标的悬赏
- **THEN** 玩家进入悬赏状态，回复已接取悬赏及预计耗时

#### Scenario: 编号非法

- **WHEN** 玩家输入非数字编号
- **THEN** 系统提示请输入有效的悬赏编号

#### Scenario: 状态不符

- **WHEN** 正在历练的玩家尝试接取悬赏
- **THEN** 系统拒绝并提示需要空闲状态

### Requirement: 奖励预确定

悬赏奖励 MUST 在接取时确定并持久化，结算时 MUST 直接读取发放而不得重算。预确定奖励 MUST 覆盖悬赏配置中的全部奖励条目（稀有物品、灵石、兽卵、装备、法决玉简、丹药、丹方、锻造图纸），MUST 在悬赏状态中作为「预计奖励」提前展示。

#### Scenario: 接取时确定

- **WHEN** 玩家接取悬赏
- **THEN** 该次悬赏的具体奖励立即确定，状态页可见预计奖励

#### Scenario: 结算不重算

- **WHEN** 玩家等待较长时间后结算
- **THEN** 发放的奖励与接取时展示的预计奖励一致

### Requirement: 悬赏进度

悬赏进行中 MUST 实时计算已过分钟数与剩余分钟数；剩余为 0 时 MUST 提示已可结算。状态 MUST 展示总耗时。

#### Scenario: 进行中

- **WHEN** 玩家在悬赏进行中查看悬赏
- **THEN** 显示「已过/总时长」与剩余时间

#### Scenario: 时间已到

- **WHEN** 已过时长不小于悬赏要求
- **THEN** 状态提示已可结算

### Requirement: 结算时间门槛

「悬赏结算」MUST 仅在玩家处于悬赏状态且存在进行中记录时可用；未到要求时长时 MUST 拒绝并提示还需等待的分钟数与总时长。

#### Scenario: 提前结算被拒

- **WHEN** 玩家在时间未到时输入「悬赏结算」
- **THEN** 系统拒绝并提示剩余分钟数，悬赏保持进行中

#### Scenario: 无进行中悬赏

- **WHEN** 玩家在没有进行中悬赏时输入「悬赏结算」
- **THEN** 系统提示当前没有进行中的悬赏

### Requirement: 结算发放

时间达标后结算 MUST 发放全部预存奖励：物品、兽卵、法决玉简、丹药、丹方、锻造图纸进入背包，装备实例化入包，灵石入账户并 MUST 受财富运势与悬赏支线事件倍率修正。结算成功后 MUST 将记录标记为已完成、玩家回到空闲，并回复悬赏名、地点、耗时与奖励内容。

#### Scenario: 成功结算

- **WHEN** 时间达标的玩家输入「悬赏结算」
- **THEN** 奖励入账，回复展示奖励与叙事，玩家回到空闲

#### Scenario: 灵石倍率

- **WHEN** 预存奖励包含灵石
- **THEN** 实际入账灵石按财富与支线事件倍率放大或保持

### Requirement: 悬赏支线事件

悬赏结算时系统 MUST 按机缘概率从当前悬赏配置的支线事件池中掷骰触发事件（事件池非空时）；若触发，效果 MUST 以通知形式呈现，可包含放大灵石奖励、增减气血、加修为、加物品或纯叙事。同一隐藏悬赏事件对同一玩家在同一悬赏 MUST 至多触发一次。

#### Scenario: 支线事件修正奖励

- **WHEN** 结算触发带奖励倍率的支线事件
- **THEN** 灵石奖励按倍率调整并在通知中说明

#### Scenario: 隐藏事件

- **WHEN** 玩家满足某隐藏悬赏事件条件
- **THEN** 该事件触发一次并推送通知，重复结算不再触发

### Requirement: 放弃悬赏

「悬赏放弃」MUST 要求玩家处于悬赏状态且存在进行中记录。放弃后 MUST 将记录标记为已放弃、玩家回到空闲，MUST NOT 发放任何奖励。

#### Scenario: 主动放弃

- **WHEN** 悬赏进行中玩家输入「悬赏放弃」
- **THEN** 悬赏被标记放弃，玩家回到空闲并收到无产出的确认回复

#### Scenario: 无悬赏可放弃

- **WHEN** 没有进行中悬赏时输入「悬赏放弃」
- **THEN** 系统提示当前没有进行中的悬赏

### Requirement: 唯一悬赏

标记为唯一的悬赏在玩家完成一次后 MUST 不可再次接取，且 MUST 不再出现在该玩家的悬赏列表中；重复接取 MUST 被拒绝并给出提示。

#### Scenario: 完成后不再出现

- **WHEN** 玩家完成一个唯一悬赏后再次查看悬赏列表
- **THEN** 该悬赏不再出现在列表中

#### Scenario: 重复接取被拒

- **WHEN** 玩家尝试再次接取已完成的唯一悬赏
- **THEN** 系统拒绝并提示该唯一悬赏已完成
