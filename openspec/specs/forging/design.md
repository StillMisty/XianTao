# 装备强化与锻造系统 详细设计

> 行为契约见同目录 spec.md；本文档为详细设计参考。

## 1. 核心概念

### 1.1 锻材三性

锻造使用独立于五行（药材）的**锻材属性体系**，数据完全隔离——药材不能锻造，锻材不能炼丹。

| 属性 | 枚举 / Key | 中文 | 影响 |
|------|-----------|------|------|
| 刚 | `RIGIDITY` | 刚性 | 成品基础攻防值 |
| 韧 | `TOUGHNESS` | 韧性 | qualityMultiplier 区间偏向 |
| 灵 | `SPIRIT` | 灵性 | 词缀数量及特殊词缀概率 |

- `MaterialAttribute` 枚举 code 为全大写，显示名为 刚性/韧性/灵性；`fromCode` 对未知值抛异常，`displayName` 容错返回原值。
- 锻材（`ItemType.MATERIAL`）在 `properties` JSONB 中存储三性值：

```json
{"RIGIDITY": 12, "TOUGHNESS": 5, "SPIRIT": 3}
```

- 只存非零值，missing key 视为 0；读取按 key 精确匹配。

### 1.2 锻造 vs 炼丹对照

| 概念 | 炼丹 | 锻造 |
|------|------|------|
| 输入物 | 药材 (HERB) | 锻材 (MATERIAL) |
| 属性体系 | 五行 (5 元素) | 锻材三性 (3 属性) |
| 配方载体 | `ItemProperties.Scroll` + `ItemType.RECIPE_SCROLL` | `ItemProperties.ForgingBlueprint` + `ItemType.FORGING_BLUEPRINT` |
| 配方学习表 | `player_pill_recipe` | `player_forging_recipe` |
| 品质判定 | 成色（上成/中成/下成） | 品质分 → 稀有度池 |
| 产出 | 丹药 (POTION)，受抗性衰减 | 装备实例 (Equipment)，受稀有度波动 |
| 核心算法 | `PillCombinationFinder` | `ForgingCombinationFinder`（同贪心算法，不同属性，最多 3 种材料） |

## 2. 锻造系统

### 2.1 锻造图纸

作为 `ItemProperties` 的密封子类型，存储于物品模板 JSONB 属性中：

```json
{
  "equipment_template_id": 42,
  "grade": 3,
  "requirements": {
    "RIGIDITY": {"min": 20, "max": 40},
    "TOUGHNESS": {"min": 10, "max": 25},
    "SPIRIT": {"min": 5, "max": 15}
  }
}
```

| 字段 | 说明 |
|------|------|
| `equipment_template_id` | 产出装备模板 ID（→ `equipment_template.id`，非 `item_template`） |
| `grade` | 图纸品阶（数据约定 1~9），提供品质分保底加成 |
| `requirements` | 三性要求，key 为属性名 (RIGIDITY/TOUGHNESS/SPIRIT)，value 为 min/max；`max=0` 视为无上限 |

图纸物品类型为 `FORGING_BLUEPRINT`，命名如「铁剑锻造图」「寒冰剑图谱」。使用后玩家学会该图纸。

### 2.2 玩家已学图纸 (player_forging_recipe)

表名 `player_forging_recipe`（无 `xt_` 前缀）。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGSERIAL | PK |
| `user_id` | BIGINT | FK → `player(id)`，ON DELETE CASCADE |
| `blueprint_template_id` | BIGINT | FK → `item_template(id)`，图纸模板 |
| `equipment_template_id` | BIGINT | FK → `equipment_template(id)`，产出装备模板 |
| `learn_time` | TIMESTAMP | 学习时间，默认 NOW() |

UNIQUE(user_id, blueprint_template_id)：不可重复学习。另有 `user_id`、`blueprint_template_id`、`equipment_template_id` 三个索引。

### 2.3 锻造流程

```
选图纸 → 放入锻材 → 累计三性总量 → 匹配约束范围 → 算品质分 → 映射稀有度池 → Roll稀有度 → 生成装备
```

#### 步骤 1：累计三性

每次锻造最多使用 **3 种锻材**（`MAX_MATERIAL_TYPES = 3`，自动/手动一致）。

```
累计刚 = Σ(锻材A RIGIDITY × 数量A + 锻材B RIGIDITY × 数量B + ...)
累计韧 = Σ(锻材A TOUGHNESS × 数量A + 锻材B TOUGHNESS × 数量B + ...)
累计灵 = Σ(锻材A SPIRIT × 数量A + 锻材B SPIRIT × 数量B + ...)
```

#### 步骤 2：约束匹配

```
图纸.刚.min ≤ 累计刚 ≤ 图纸.刚.max
图纸.韧.min ≤ 累计韧 ≤ 图纸.韧.max
图纸.灵.min ≤ 累计灵 ≤ 图纸.灵.max
```

全部满足 → 进入品质判定。否则 → 锻造失败，**材料不消耗**（自动模式报缺少/超限属性，手动模式报不匹配任何图纸，均在扣减前抛出）。

#### 步骤 3：品质分计算（同丹药成色算法）

```
每项属性的达标度 = 1 - |实际值 - 范围中心| / 范围半宽
范围中心 = (max + min) / 2
范围半宽 = (max - min) / 2（精确值时达标度为 1）
单项达标度下限截断为 0

品质分 = Σ(三项达标度) / 3
```

图纸品阶 `grade` 提供品质分保底加成：`最终分 = 品质分 + grade × 0.02`。

### 2.4 品质分 → 稀有度池

按**加成后的最终分**选择稀有度权重池，加权随机 roll：

| 最终分 | 稀有度权重池 |
|--------|------------|
| ≥ 0.9 | LEGENDARY 10 : EPIC 40 |
| ≥ 0.7 | EPIC 30 : RARE 40 : COMMON 10 |
| ≥ 0.5 | RARE 20 : COMMON 50 : BROKEN 10 |
| < 0.5 | COMMON 30 : BROKEN 50 |

稀有度加权随机 roll 出后，`qualityMultiplier` 和词缀在对应稀有度范围内随机生成（与掉落装备一致）：

| 稀有度 | 品质系数范围 | 词条数 |
|--------|------------|--------|
| BROKEN（破旧） | 0.80 ~ 0.99 | 0 |
| COMMON（普通） | 1.00 ~ 1.15 | 1 |
| RARE（稀有） | 1.16 ~ 1.35 | 1~2 |
| EPIC（史诗） | 1.36 ~ 1.60 | 2~3 |
| LEGENDARY（传说） | 1.61 ~ 2.00 | 3~4 |

词条数值：属性词条（力道/根骨/身法/悟性）1~4 随机；特殊词条（吸血 LIFE_STEAL / 寻宝 TREASURE_HUNT）固定 5，仅传说稀有度入池。

#### 品质计算示例

```
图纸 寒冰剑图: RIGIDITY[20~40] TOUGHNESS[10~25] SPIRIT[5~15]

投入材料后累计: 刚=30 韧=18 灵=10

刚达标度 = 1 - |30-30|/10     = 1.00
韧达标度 = 1 - |18-17.5|/7.5  = 0.93
灵达标度 = 1 - |10-10|/5      = 1.00

品质分 = (1.00 + 0.93 + 1.00) / 3 = 0.98
最终分 = 0.98 + grade × 0.02（grade=3 时 1.04）→ 可 roll LEGENDARY/EPIC
```

### 2.5 自动锻造流程

「锻造 [图纸名]」：

1. 按名称模糊匹配玩家已学图纸（`contains`，取第一个命中）；未命中时若背包有同名图纸，提示先「使用」学习；否则报「未找到名为「X」的锻造图纸」。
2. 校验图纸数据完整（`requirements` 非空）。
3. 取背包全部 `MATERIAL`；无锻材报「锻材不足，无法锻造」。
4. 贪心算法在最多 3 种锻材内搜索组合（按整体缺口贡献挑选，份数 `ceil(缺口/单份值)` 且不超过剩余量）。
5. 有属性不足 → 报「缺少锻材属性：<原文 key 列表>」；有属性超限 → 报「锻材属性超过上限：<中文名>」；均不消耗材料。
6. 计算品质分 → 稀有度 roll → 按名称扣减实际用量 → 用 `EquipmentFactory` 生成装备（名称「模板名-稀有度名」）并入库，回复装备名、稀有度、品质分百分比与消耗明细。

### 2.6 手动锻造流程

「锻造 [锻材名数量 ...]」（不带图纸名）：

1. 输入按空白拆分，每段需满足「非数字名称 + 正整数数量」格式（如 `玄铁矿石3`），最多 3 段，超出报「最多只能使用3种锻材」；全部无效报格式错误。
2. 逐段在背包 `MATERIAL` 中按名称模糊匹配，未命中段静默跳过。
3. 累计三性后遍历已学图纸，取**第一个**满足全部约束的图纸。
4. 命中后按实例 ID 逐条扣减输入数量（数量不足报错并回滚），内联生成装备（名称、品质系数、词条数量与词条数值规则与自动锻造一致；基础属性加成只写入大于 0 的四维）。
5. 无图纸匹配报「锻材三性不匹配任何锻造图纸」，不消耗材料。

### 2.7 图纸获取途径

- 灵石购买（NPC 商店）
- 地图探索掉落图纸卷轴
- 悬赏奖励
- 秘境产出

## 3. 强化系统

### 3.1 强化上限

| 稀有度 | 最高强化等级 |
|--------|------------|
| BROKEN | +3 |
| COMMON | +5 |
| RARE | +8 |
| EPIC | +12 |
| LEGENDARY | +18 |

强化前校验：当前等级 ≥ 上限时拒绝并提示上限值。装备通过名称或背包编号解析（`resolveAnyEquipment`），重名多件时列出候选（编号 + 名称 + 稀有度）要求精确指定。

### 3.2 三阶段设计

| 阶段 | 成功率来源 | 消耗 | 图纸要求 |
|------|-----------|------|---------|
| +0 → +3 | **100%**（必定成功） | 纯灵石 | 不需要 |
| +4 → +9 | **固定概率**（80% → 55% 递减）× 稀有度修正 | 灵石 + 锻材 | 不需要 |
| +10 → 上限 | **品质分 = 成功率**（完美命中 = 100%） | 灵石 + 锻材 | **必须持有图纸** |

### 3.3 成功率曲线

#### +4 → +9（固定概率）

```
+4: 80%   +5: 75%   +6: 70%
+7: 65%   +8: 60%   +9: 55%
```

稀有度修正：传说 ×0.9，史诗 ×0.95，稀有 ×1.0，普通 ×1.05，破旧 ×1.1。实际成功率 = 基础概率 × 稀有度修正。

#### +10 → 上限（品质分 = 成功率）

强化消耗的材料同样需要匹配三性约束。约束取自装备对应的**锻造图纸**，并按强化等级放大：

```
强化约束 = 图纸基础约束 × (1 + (强化目标等级 - 9) × 0.3)
min/max 分别乘以系数后四舍五入取整

例如强化到 +12：
  图纸 RIGIDITY[20~40] → 强化约束 RIGIDITY[20~40] × (1 + 3×0.3) = [38~76]
```

材料累计三性越接近约束中心，成功率越高：

```
成功率 = calculateQualityScore(材料三性总量, 强化约束)

完美匹配中心点 → 100%
有一定偏差     → 线性下降（单项截断为 0）
```

自动模式用贪心算法填充到约束下限（不追求中心点）；手动模式可由玩家精确配比追求中心匹配。手动模式在计算前会校验累计三性是否落在约束内，越界直接报「锻材不满足强化约束」。

### 3.4 消耗

#### 灵石消耗

```
灵石消耗 = (int)(50 × 稀有度系数 × (1 + 目标等级 × 0.3))

基础值 = 50（常量 BASE_STONE_COST）
稀有度系数: BROKEN=0.5, COMMON=1, RARE=2, EPIC=4, LEGENDARY=8
```

示例：强化传说装备到 +15

```
50 × 8 × (1 + 15 × 0.3) = 400 × 5.5 = 2200 灵石
```

灵石不足时报「灵石不足（需要 N，当前 M）」；灵石通过原子条件扣减。

#### 锻材消耗（+4 以上）

- +4 → +9：按稀有度的**通用三性约束**选材/校验（见下表），自动模式从背包贪心选材，手动模式校验玩家配比。
- +10 → 上限：消耗锻材须满足强化约束（图纸约束 × 增幅系数），实际消耗的材料数量由玩家自行选择（手动）或系统贪心填充（自动），只要累计三性落在约束范围内即可。
- 灵石与锻材在 Roll 成功率**之前**扣除，失败不退还。

通用强化约束表（+4 → +9 按稀有度）：

| 稀有度 | RIGIDITY | TOUGHNESS | SPIRIT |
|--------|----------|-----------|--------|
| BROKEN | 3 ~ 8 | 2 ~ 5 | 0 ~ 3 |
| COMMON | 5 ~ 15 | 3 ~ 10 | 1 ~ 5 |
| RARE | 10 ~ 25 | 5 ~ 15 | 3 ~ 10 |
| EPIC | 20 ~ 40 | 10 ~ 25 | 5 ~ 15 |
| LEGENDARY | 30 ~ 60 | 15 ~ 40 | 10 ~ 25 |

### 3.5 失败惩罚

装备**不会损坏**。失败只降 1 级（当前等级 >0 时 `forgeLevel -= 1`，最低 +0），材料与灵石正常消耗。回复包含新等级与实际成功率。

### 3.6 图纸门槛逻辑

- +0 → +9：未持有图纸也可强化（安全期/通用约束）。
- +10 → 上限：**必须在 `player_forging_recipe` 中找到该装备模板对应的图纸**。若装备为掉落的（无对应图纸），强化 +10 时直接报「强化+10及以上需要持有对应锻造图纸」，无法继续。

这赋予锻造装备更大的成长空间——自己锻造的装备可以强化到满，掉落装备止步 +9。

### 3.7 里程碑奖励

每次强化成功达到对应等级时触发：

| 里程碑 | 奖励（实际实现） |
|--------|------|
| +5 | 从已有**非特殊**词条中随机一条 +1 |
| +10 | 从全部已有词条（含特殊词条）中随机一条 +1 |
| +15 | 若词条数未达稀有度上限，解锁一条新随机词条；属性词条 1~4、特殊词条固定 5，传说才从特殊词条池抽取，且排除已存在词条 |

没有可加成的词条时里程碑不产出奖励（回复中无里程碑文案）。

### 3.8 自动 vs 手动强化

| 模式 | 命令 | 行为 |
|------|------|------|
| 自动 | `强化 [装备名/编号]` | +0→+3 直接扣灵石；+4→+9 自动从背包贪心选材（满足通用约束下限）；+10→上限 按放大约束贪心选材 |
| 手动 | `强化 [装备名/编号] [锻材名数量 ...]` | 玩家精确指定锻材及数量（最多 3 种），系统校验三性累计落在约束范围内后执行强化 |

手动模式让玩家在 +10 以上阶段可以追求完美中心匹配 → 100% 成功率。

实现细节：

- 手动强化在安全期（+0→+3）仍走必定成功路径，输入的锻材被忽略且不消耗（只扣灵石）。
- 自动强化 +4 以上找不到满足下限的材料时，报缺少锻材属性；+10 以上报「锻材不满足强化约束」。
- 强化改变装备属性后驱逐装备列表与详情缓存。
- `EnhanceResultVO` 字段：成功标志、文案、装备 ID/名称、新等级、原等级、成功率、灵石消耗、消耗材料、里程碑奖励；成功结果中的「成功率」字段在 +10 以上显示 0（未回传实际值，命令回复不展示该字段）。

## 4. 架构设计

### 4.1 新增类型

| 层 | 新增项 | 说明 |
|----|--------|------|
| enum | `ItemType.FORGING_BLUEPRINT` | 锻造图纸物品类型 |
| entity | `ItemProperties.ForgingBlueprint` | `sealed` 子类型 (equipmentTemplateId, grade, requirements) |
| entity | `PlayerForgingRecipe` | 玩家已学锻造图纸实体（`domain/forge/entity`） |
| vo | `ForgingResultVO` | 锻造结果（message、装备 ID/名称、稀有度、品质分、消耗材料、材料总量） |
| vo | `ForgingRecipeVO` | 图纸详情（图纸模板 ID/名称、品阶、装备模板 ID/名称、三性要求） |
| vo | `EnhanceResultVO` | 强化结果（成功/失败、文案、装备、新旧等级、成功率、灵石消耗、消耗材料、里程碑） |

### 4.2 数据表

```sql
CREATE TABLE player_forging_recipe (
    id                      BIGSERIAL PRIMARY KEY,
    user_id                 BIGINT NOT NULL,
    blueprint_template_id   BIGINT NOT NULL,
    equipment_template_id   BIGINT NOT NULL,
    learn_time              TIMESTAMP NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_user_forging_recipe UNIQUE (user_id, blueprint_template_id),
    CONSTRAINT fk_player_forging_recipe_user FOREIGN KEY (user_id) REFERENCES player(id) ON DELETE CASCADE,
    CONSTRAINT fk_player_forging_recipe_blueprint FOREIGN KEY (blueprint_template_id) REFERENCES item_template(id),
    CONSTRAINT fk_player_forging_recipe_equipment FOREIGN KEY (equipment_template_id) REFERENCES equipment_template(id)
);
```

### 4.3 服务拆分

```
ForgingService              → 公开 API：锻造入口、图纸学习、已学列表/详情
ForgingCombinationFinder    → 材料匹配 + 品质分计算 + 稀有度映射 + 装备生成
EnhancementService          → 公开 API：强化入口、装备解析校验、自动/手动分发
EnhancementCore             → 上限表、成功率表、稀有度修正、灵石消耗、通用/放大约束、
                              成功/失败结算、里程碑奖励、材料扣减
SafeEnhanceRegime           → +0→+3：必定成功，仅灵石
ProbabilisticEnhanceRegime  → +4→+9：通用约束 + 固定概率 × 稀有度修正
BlueprintEnhanceRegime      → +10→上限：图纸约束放大 + 品质分=成功率
```

### 4.4 新增 ItemUseHandler

```
ForgingBlueprintUseHandler  → 使用 FORGING_BLUEPRINT 类型物品时学习图纸
                               consumesInternally() = false（由 ItemUseService 统一扣减）
```

### 4.5 命令接口

| 命令 | 功能 |
|------|------|
| `锻造列表` | 查看已学锻造图纸（编号、名称、品阶 → 产出装备） |
| `锻造 [图纸名]` | 自动配材锻造 |
| `锻造 [锻材名数量 ...]` | 手动配材锻造（最多 3 种锻材） |
| `强化 [装备名/编号]` | 自动强化（系统自动选材） |
| `强化 [装备名/编号] [锻材名数量 ...]` | 手动强化（最多 3 种锻材，精确控制配比追求高成功率） |
| `使用 [图纸名]` | 使用图纸卷轴学习（走 ItemUseHandler） |

输入格式为「名称紧连数量」（如 `玄铁矿石3`），非 `×N` 记号；命令分发按首段是否为「名称+数量」判定手动/自动。

### A. 实现现状（文档已修正）

- **三性显示名为 刚性/韧性/灵性**：枚举与数据 key 为全大写 `RIGIDITY/TOUGHNESS/SPIRIT`，`displayName` 容错返回原值。
- **表名与 FK**：`player_forging_recipe`（无 `xt_` 前缀），`equipment_template_id` FK → `equipment_template`（装备模板独立于 `item_template`）。
- **+4→+9 通用约束为按稀有度的完整三性区间表**：BROKEN 3~8/2~5/0~3 … LEGENDARY 30~60/15~40/10~25，自动选材以区间下限为目标。
- **灵石消耗使用强化目标等级**：`50 × 稀有度系数 × (1 + 目标等级 × 0.3)`，与文档示例一致；灵石在 Roll 成功率之前原子扣减，失败不退还。
- **失败降级保底 +0**：`currentLevel > 0 ? currentLevel - 1 : 0`，装备不损坏，灵石与锻材不退。
- **装备生成细节**：名称「模板名-稀有度名」，品质系数在稀有度区间内均匀随机，属性词条 1~4、特殊词条固定 5，传说才从特殊词条池抽取。
- **手动锻造不带图纸名**：遍历全部已学图纸取第一个满足约束者；自动锻造才按图纸名匹配。
- **材料扣减方式**：锻造自动按名称匹配首个同名材料、手动按实例 ID 精确扣减；强化两种模式均按名称匹配首个同名材料（同名多行时可能扣到第一行，当前材料入库均继承模板属性，该场景不可达）。
- **锻造失败不消耗材料**：自动/手动均在约束不满足时、扣减前报错（与文档一致）。

### B. 保留代码设计

- **+10 起必须持有对应图纸，无「50% 尝试」路径**：自己锻造的装备可强化到满、掉落装备止步 +9，锻造产出因此有明确的长线价值；直接报错比概率尝试更可预期，避免玩家在无图纸时反复赌失败。
- **自动强化填充到约束下限、不追求中心点**：自动是保底便捷路径，手动可精确配比追求中心匹配（完美中心 = 100% 成功率）；若自动也追中心，手动模式将失去意义。
- **自动强化不校验约束上限**：+4→+9 成功率固定（基础 × 稀有度修正），超上限不影响结果；+10 以上超限仅使品质分单项截断为 0，手动模式仍严格校验 min/max 并报「锻材不满足强化约束」。两种模式定位清晰。
- **里程碑奖励的限制规则**：+5 只强化非特殊词条、+10 含特殊词条、+15 新增词条排除已存在 key 且仅传说从特殊词条池抽取、无可用词条时不产出奖励；与稀有度词条数/词条池设计一致，避免奖励越界或落空。
- **手动强化在 +0→+3 忽略输入锻材**：安全期仍必定成功、只扣灵石，与自动模式一致，避免误操作白白损失锻材（输入了不存在/数量不足的锻材仍会在解析阶段报错）。
