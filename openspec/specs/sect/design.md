# 宗门系统 详细设计

> 行为契约见同目录 spec.md；本文档为详细设计参考。

## 1. 概述

宗门是玩家可加入的持久性组织。**宗灵**是宗门本身的灵性化身，LLM 驱动，玩家通过自然语言与宗灵对话来执行所有宗门操作。

### 设计原则

- **文字挂机 MUD**：所有交互异步，无实时通信、无定时任务
- **宗灵统一入口**：除创建、退出、解散外，所有宗门事务通过 `宗灵 [自然语言]` 完成
- **零玩家间交易**：宗门资金/贡献均为玩家↔系统流转
- **师徒与宗门无关**：师徒关系独立于宗门存在，拜师不受宗门身份限制，宗门变动不影响师徒关系（代码中存在未使用的 `SECT_APPRENTICE_MUST_FOLLOW_MASTER` / `SECT_MASTER_MUST_MANAGE_APPRENTICE` 错误码，但无任何联动逻辑）
- **退宗遗忘**：从宗门习得的共享功法，退宗后自动遗忘，防止功法外流

## 2. 宗灵

### 2.1 定义

宗灵不是长老、不是 NPC，**是宗门本身的意志体现**。创建宗门时 LLM 赋予其灵性——剑宗的宗灵可能是一柄傲雪古剑的剑意，丹宗的宗灵可能是一缕药香凝成的老叟。玩家跟宗灵说话，就是在跟宗门本身交流。

### 2.2 宗灵 vs 地灵

| | 地灵 | 宗灵 |
|---|---|---|
| 身份 | 个人福地守护灵 | 宗门意志化身 |
| 范围 | 单人 | 全宗共享 |
| 情绪 | MBTI + 好感度驱动 | 无个体情绪，反映宗门状态 |
| 工具 | 操作福地（种植/建造/收获） | 管理宗门事务 |
| 记忆 | 与单人的对话历史 | 统一 `chat_history` 表，按成员分别记录（ChatType=SECT，窗口 10 条） |

### 2.3 宗灵操作范围（工具名以代码为准）

宗门概况（名称、等级、资金、人数、事件、公告）与个人贡献值在对话时**注入 system prompt**，不走 tool。对话前惰性结算灵脉产出。

其余操作通过 Tool Calling（Spring AI `@Tool`），根据调用者职位**选择性注册**：

| 权限 | 工具（代码名） | 说明 |
|------|------|------|
| 全员 | `checkSectShop` | 查看贡献商店商品列表（原 `queryShop`） |
| 全员 | `exchangeShopItem` | 用贡献兑换商品 |
| 全员 | `checkSharedSkills` | 查看共享功法列表（原 `querySharedSkills`） |
| 全员 | `learnSharedSkill` | 消耗贡献学习共享功法 |
| 全员 | `offerSkillJade` | 提交背包中的功法玉简到宗门，获 300 贡献（原 `submitSkillJade`） |
| 全员 | `offerSpiritStones` | 捐献灵石 → 贡献（灵石 × 0.1）+ 宗门资金等额（原 `donateStones`） |
| 全员 | `checkSectBuildings` | 查看建筑状态 |
| 长老+ | `inviteMember` | 邀请散修玩家入宗 |
| 长老+ | `expelMember` | 踢出弟子（原 `kickMember`） |
| 长老+ | `postNotice` | 发布/更新宗门公告 |
| 长老+ | `removeSharedSkill` | 下架共享功法（LISTED → PENDING，已学者不受影响） |
| 长老+ | `publishSharedSkill` | 上架共享功法（PENDING → LISTED）（原 `listSharedSkill`） |
| 长老+ | `listItem` | 将物品上架到贡献商店（选品 + 定价 + 库存，`stock=-1` 无限；同名更新） |
| 宗主 | `appointMember` | 任命/罢免长老（含宗主传承） |
| 宗主 | `upgradeSect` | 消耗宗门资金提升宗门等级 |
| 宗主 | `expandMembers` | 消耗宗门资金扩充成员上限（+5） |
| 宗主 | `buildStructure` | 消耗宗门资金建造建筑 |
| 宗主 | `upgradeBuilding` | 消耗宗门资金升级建筑 |
| — | `dismissSect` | 解散宗门（保留为命令，不走宗灵） |
| — | `queryTasks` | **无对应实现**（任务系统未落地，见 §9） |

> 工具按职位分层注册：弟子（MEMBER）只有 `SectMemberTools`；长老（ELDER）额外注册 `SectElderTools`；宗主（LEADER）再注册 `SectLeaderTools`。低职位无法越权调用。
> 注意：服务层若干宗主操作（`upgradeSect`/`expandMembers`/`buildStructure`/`upgradeBuilding`/`appointMember`）的守卫实际是 `canManage()`（含长老），职位约束由工具注册完成。

### 2.4 保留的命令

| 指令 | 原因 |
|------|------|
| `宗门` | 查看宗门总览 |
| `宗门创建 [名称] [道统描述?]` | 无宗门无宗灵 |
| `宗门退出` | 急迫操作不宜对话（**宗灵无退出工具**，文档「可通过宗灵对话退出」未实现） |
| `宗门解散` | 毁灭性操作需明确指令 |

玩家只能被邀请加入宗门，不可自行申请。

## 3. 宗门创建（LLM 注入）

### 3.1 创建方式

| 类型 | 说明 |
|------|------|
| **玩家创建** | 达到金丹期 + 消耗 5000 灵石 + 可选道统描述 |

### 3.2 创建流程（以代码为准）

```
玩家：宗门创建 青云宗 以剑入道，追求一击必杀
  ↓
① 验证境界 ≥ 金丹期、未在宗门、名称唯一（LLM 调用在事务外）
② LLM 根据道统描述生成宗灵身份：
   - 宗门诗号（4-7 言对仗句，截断上限 100 字）
   - 道统简述（提示词要求 100 字内，截断上限 200 字）
   - 宗灵人格种子（提示词要求 50 字内，截断上限 100 字）
③ 若无道统描述，LLM 据宗门名生成默认；LLM 失败回退默认身份，不阻断创建
④ 玩家可控文本先经 PromptSanitizer 净化（200 字）
⑤ 短事务：扣减 5000 灵石 + 创建宗门（Lv.1，成员上限 10），玩家任宗主
⑥ 初始资金池 = 2000 灵石；description 复用 LLM 道统
⑦ 返回诗号 + 创建成功信息
```

> 与文档差异：截断上限以代码为准（诗号 100 / 道统 200 / 人格 100）；LLM 失败有默认身份兜底。

## 4. 层级结构

宗门设三级职位，由上至下：

| 职位 | 数量 | 权限 |
|------|------|------|
| **宗主** | 1 人 | 全部权限 |
| **长老** | 不限制 | 邀请/踢出成员、发布公告、上下架功法、上架商店商品 |
| **弟子** | — | 贡献商店兑换、学习/提交功法、捐献 |

### 4.1 权限矩阵（以代码 `SectPosition` 判定方法为准）

通用规则：上任可管理下任（只能处置比自己职位低的成员）。

| 操作 | 宗主 | 长老 | 弟子 | 代码判定 |
|------|:----:|:----:|:----:|------|
| 任命/罢免（含传承） | ✅ | —（仅工具未注册） | — | `canManage()` + 工具注册 |
| 解散宗门 | ✅ | — | — | `position == LEADER` |
| 宗门升级 | ✅ | —（仅工具未注册） | — | `canManage()` + 工具注册 |
| 宗门扩容 | ✅ | —（仅工具未注册） | — | `canManage()` + 工具注册 |
| 建造/升级建筑 | ✅ | —（仅工具未注册） | — | `canManage()` + 工具注册 |
| 发布公告 | ✅ | ✅ | — | `canPostNotice()` |
| 踢出成员 | 下任 | 下任 | — | `canKick()` + `isHigherThan()` |
| 邀请成员 | ✅ | ✅ | — | `canInvite()` |
| 下架功法 | ✅ | ✅ | — | `canManageSkills()` |
| 上架功法 | ✅ | ✅ | — | `canManageSkills()` |
| 上架商店商品 | ✅ | ✅ | — | `canManage()` + 工具注册 |
| 贡献商店兑换 | ✅ | ✅ | ✅ | 成员即可 |
| 共享功法学习/提交 | ✅ | ✅ | ✅ | 成员即可 |
| 捐献灵石 | ✅ | ✅ | ✅ | 成员即可 |

> "下任" = 可管理自己以下职位的成员，不可管理同职位或上级。宗主不可被踢出。

## 5. 成员管理

### 5.1 成员上限

- **初始上限**：10 人
- **升级扩容**：每次升级自动 +5
- **独立扩容**：消耗 `5 × 500 = 2500` 灵石增加 5 个槽位（通过宗灵）

### 5.2 加入方式

| 方式 | 说明 | 入口 |
|------|------|:----:|
| 受邀加入 | 有邀请权限的成员通过宗灵邀请，**邀请即入宗（无接受确认流程）** | 宗灵 |

玩家不可自行申请加入宗门。

> 实现现状：邀请校验 `findByUserId()` 是否存在成员记录（**包含退宗/被踢后保留的冷却记录**）。因此有退宗记录的玩家实际会被拒绝（提示已在他宗），`isOnCooldown` 分支不可达——退宗/被踢后无法再次被邀请。冷却记录无清理路径。

### 5.3 师徒与宗门

师徒关系与宗门完全独立：拜师不受宗门身份限制，入宗/退宗/解散均不影响师徒关系。（代码无宗门联动逻辑。）

### 5.4 主动退出

- 通过 `宗门退出` 命令退出（宗灵无对应工具）
- **惩罚**：贡献清零，24h 冷却，**已学共享功法自动遗忘**
- 宗主且宗门还有其他成员时不可退出，须先 `宗门解散`；宗主为最后一名成员时退出即解散宗门

### 5.5 踢出成员

- 宗主可踢出长老和弟子，长老可踢出弟子
- 不可踢出自己、不可踢出同职位或上级（宗主不可被踢）
- 被踢出者贡献清零，24h 冷却，**已学共享功法自动遗忘**

## 6. 贡献值体系

### 6.1 个人贡献值

| 获取途径 | 贡献值 | 说明 |
|---------|--------|------|
| 捐献灵石 | 捐献量 × 0.1（向下取整） | 同时增加宗门资金等额；代码只要求 amount > 0 |
| 提交功法玉简 | 300/份 | 一次性奖励，消耗玉简 |
| 传功香火 | 学费 × 15%（至少 1） | 他人学习你呈献的共享功法时回流；呈献者已离宗或自学者不回流 |

### 6.2 宗门资金池

- 来源：成员捐献、灵脉产出
- 用途：宗门升级、成员扩容、**宗门建筑建造/升级**

### 6.3 宗门贡献商店

- 长老/宗主可通过宗灵将物品上架到贡献商店（选品 + 定价 + 库存，`stock = -1` 为无限）
- 同名商品重复上架时更新定价与库存（改价补货）
- 弟子消耗贡献值兑换商品；药园灵药由建筑自动上架供应
- 定价必须 > 0；库存必须 > 0 或 -1；兑换时原子扣贡献 + 原子扣库存

## 7. 宗门建筑

宗门资金的核心消耗渠道。每栋建筑可独立建造和升级，每类只能建一座。

### 7.1 建筑列表（以代码枚举为准）

| 建筑 | 代码 | 效果（每级） | 建造 | 满级 | 满级总耗 | 联动系统 | 效果接入 |
|------|------|------|-----:|:----:|------:|------|------|
| **藏经阁** | SCRIPTURE_PAVILION | +3 共享功法位 | 3,000 | 5 | 15,000 | 法决 | ✅ 已接入 |
| **练功房** | TRAINING_ROOM | 修炼修为 +3% | 2,000 | 5 | 10,000 | 历练 | ⚠️ 方法已定义，未接入 |
| **炼丹房** | ALCHEMY_CHAMBER | 炼丹品质评分 +5% | 2,000 | 3 | 6,000 | 炼丹 | ⚠️ 方法已定义，未接入 |
| **灵脉** | SPIRIT_VEIN | 日产灵石 100 注入宗门资金 | 5,000 | 3 | 15,000 | 经济 | ✅ 已接入 |
| **锻造坊** | FORGE_WORKSHOP | 强化费用 -5% | 2,000 | 3 | 6,000 | 装备强化 | ⚠️ 方法已定义，未接入 |
| **护阵** | GUARD_ARRAY | 受伤 -3% | 4,000 | 3 | 12,000 | 战斗 | ⚠️ 方法已定义，未接入 |
| **药园** | HERB_GARDEN | 解锁宗门专属灵药（商店上架） | 3,000 | 3 | 9,000 | 丹药/福地 | ✅ 已接入 |

### 7.2 建筑规则

- 建筑等级独立于宗门等级，未建造时表中无行
- 宗主消耗宗门资金建造/升级（每次升级费用 = 建造费用）；建造/升级走原子条件扣款
- 效果对所有宗门成员自动生效，实时读取——**但仅藏经阁/灵脉/药园已接入消费方**（见 7.1 末列）
- 建筑总费用为宗门资金提供长期消耗目标

### 7.3 特殊建筑规则

**灵脉**：
- 惰性结算，**在宗灵对话开始时**计算距上次结算时间的产出（`小时 × 等级 × 100 / 24`），不足 1 小时或产出为 0 不结算
- `sect.last_vein_payout` 记录上次结算时间，首次以 `created_at` 起算

**药园**：
- 建造/升级时自动向贡献商店上架对应品阶灵药并补满库存（每级 10 份）：
  - Lv.1：灵芝、茯苓（15 贡献）
  - Lv.2：追加 血参、金银花（40 贡献）
  - Lv.3：追加 雪莲、紫丹参（60 贡献）
- 灵药为宗门商店专属供应渠道，成员无需自建福地灵田也可稳定获得炼丹药材

**炼丹房**：
- 品质加成作用于炼丹评分（`baseScore × (1 + 等级 × 0.05)`），提高产出上成品概率（加成方法已定义，尚未接入炼丹结算）

## 8. 功法传授

### 8.1 流程（以代码为准）

```
玩家 A：宗灵 我要提交功法
  → 消耗背包中的功法玉简（物品模板须携带 SkillJade 属性）
  → 功法入库（状态 = PENDING），玩家 A 获得 300 贡献
  → 同一功法不可重复提交；功法位（listed+pending）受藏经阁等级限制

长老/宗主：宗灵 上架烈焰诀
  → 功法状态 PENDING → LISTED，全员可学；上架同样校验功法位上限

玩家 B：宗灵 我想学烈焰诀
  → 校验 LISTED、未学过、境界达到 levelRequirement
  → 扣减玩家 B 贡献（贡献 = 功法 levelRequirement × 50，原子扣减）
  → 学费的 15%（至少 1）作为「传功香火」回流给呈献者玩家 A（已离宗或自学者不回流）
  → 通知 A（GameEvent，类别 SECT_EVENT）：「道友B修习了你呈上的功法，香火已入账」
  → 传授功法（player_skill.source_sect_id = 宗门ID）

长老/宗主：宗灵 下架烈焰诀
  → 功法状态 LISTED → PENDING，已学者不受影响

玩家 B 退出宗门
  → 系统自动删除玩家 B 已学的所有宗门共享功法（按 source_sect_id）
  → 功法原样留在宗门，下个弟子接着学
```

功法列表展示呈献者署名：`[编号] 烈焰诀 (Lv10+ | 500贡献 | 张三 呈)`。

### 8.2 防泛滥规则

| 规则 | 说明 |
|------|------|
| **退宗遗忘** | 退宗/被踢/宗门解散后，该玩家所有共享功法自动删除 |
| **同一功法不可重复提交** | 已存在的功法不能再次提交（UNIQUE sect+skill） |
| **宗门功法位上限** | 受藏经阁建筑等级控制（基础 3 + 每级 +3）；提交时按 listed+pending 计，上架时按 listed 计 |
| **消耗品提交** | 提交时消耗功法玉简，不是复制 |

## 9. 宗门动态（未实现）

> 原设想的「宗门集体目标」（资金进度条+周期结算）已否决——与低频挂机定位不符，且成员间交互价值有限。
> 宗门的交互感由以下机制承担：贡献商店经营（长老上架选品定价）、共享功法署名与传功回流、宗灵对话。
> 后续若需全宗协作内容，优先考虑世界 Boss 等玩法层载体而非任务系统。

**代码现状**：`sect` 表有 `last_event_type` / `last_event_text` / `last_event_time` / `event_expires_at` 列，`SectOverviewVO` 与宗灵 Prompt 会读取 `last_event_text`，但**没有任何写入方**；`sect_task` / `sect_task_progress` 表与任务工具均不存在。

## 10. 宗门升级

宗主消耗宗门资金提升宗门等级（原子条件扣款）：

| 目标等级 | 消耗资金 | 效果 |
|:------:|---------|------|
| Lv.1 → Lv.2 | 5,000 | 成员上限 +5 |
| Lv.2 → Lv.3 | 15,000 | 成员上限 +5 |
| Lv.3 → Lv.4 | 30,000 | 成员上限 +5 |
| Lv.4 → Lv.5 | 50,000 | 成员上限 +5 |

等级上限 Lv.5（`sect.level CHECK 1~5`）。

- 宗主可通过宗灵 `任命 [道号] 为宗主` 传承（`appointMember` + LEADER 职位）
- 原宗主自动降为长老，`sect.leader_id` 同步更新

## 12. 玩家指令

### 12.1 直接命令（以 `SectListener` 为准）

| 指令 | 说明 | 要求 |
|------|------|------|
| `宗门` | 查看宗门总览（名称、品阶、宗主、成员、资金、我的贡献/职位、公告、事件、成员列表） | 已加入宗门 |
| `宗门创建 [名称] [道统?]` | 创建宗门，LLM 生成宗灵身份 | 金丹期 + 5000 灵石 |
| `宗门退出` | 退出宗门（贡献清零，24h 冷却，遗忘功法） | 已加入宗门 |
| `宗门解散` | 解散宗门 | 宗主 |

### 12.2 宗灵对话

```
宗灵 [自然语言]

示例：
```

## 迁移评估：设计取舍

> 原设计文档与实现的差异评估。A 实现现状（文档已按代码修正）；B 保留代码设计（更合乎玩法）；C 按设计修正（设计意图更优，条目标注已修/待修）；D 未实现（待办）；E 缺陷修复。

### A. 实现现状（文档已修正）

- **表名与字段**：实际为 `sect` / `sect_member` / `sect_building` / `sect_shared_skill` / `sect_shop_item` / `chat_history`（无 `xt_` 前缀）；`chat_history.role` 为 VARCHAR(16) 且含 `extra_data`。
- **工具名**：`queryShop`→`checkSectShop`、`querySharedSkills`→`checkSharedSkills`、`submitSkillJade`→`offerSkillJade`、`donateStones`→`offerSpiritStones`、`kickMember`→`expelMember`、`listSharedSkill`→`publishSharedSkill`、`queryBuildings`→`checkSectBuildings`；新增 `listItem`（长老上架商店商品）。
- **权限守卫**：`upgradeSect` / `expandMembers` / `buildStructure` / `upgradeBuilding` / `appointMember` 的服务层守卫是 `canManage()`（含长老），宗主限定由工具仅注册给 LEADER 实现；当前无其他调用方，不构成越权路径。
- **LLM 身份截断**：诗号 ≤100、道统 ≤200、人格 ≤100（文档要求 50/100 作废）。
- **创建资金错误码**：创建实际由灵石扣减抛 `SPIRIT_STONES_INSUFFICIENT`（文案正确）；`SECT_CREATE_FUNDS_INSUFFICIENT` 无调用方。
- **师徒联动**：`SECT_APPRENTICE_MUST_FOLLOW_MASTER` / `SECT_MASTER_MUST_MANAGE_APPRENTICE` 无调用方；师徒与宗门保持相互独立。

### B. 保留代码设计

- **宗灵无退出/解散工具，保留 `宗门退出`/`宗门解散` 命令**：退出涉及贡献清零与功法遗忘、解散不可逆，显式命令可避免 LLM 误判触发；急迫与毁灭性操作不宜对话。
- **邀请即入宗（无接受确认）**：无主动推送，等待确认会让邀请长期悬置；邀请权本身是长老/宗主的社交资源，被邀请者可随时自行退出。
- **灵脉在宗灵对话开始时惰性结算**：结算挂在唯一的资金消费入口，保证花钱时数值最新；`宗门` 总览保持只读，避免查看操作写库与缓存失效。
- **传功香火 `max(1, 学费 × 15%)` 且呈献者须仍在同一宗门**：保底 1 点让低价功法也有回流反馈；离宗者不再回流，与「退宗遗忘」一致。
- **不实现宗门任务/集体目标**：与低频挂机定位不符（§9 已否决），成员交互由贡献商店、共享功法香火、宗灵对话承担。
