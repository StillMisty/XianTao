# Spec Delta

## Purpose

定义交易的行为契约：以掌柜自然语言对话为入口的买卖（浏览、估价、砍价、收购、出售、快速回收）、装备估价与随机品质购买、商铺懒补货懒调价、价格受世界事件影响的规则、交易原子性与错误反馈、玩家之间不可交易的边界，以及调货预定与旅行商人临时商铺。价格公式、数据模型与配置细节见 `openspec/specs/trade/design.md`。

## ADDED Requirements

### Requirement: 调货下单与到货

系统 MUST 支持玩家在掌柜对话中为店铺无货或售罄的物品下单调货：下单 MUST 收取总价的 10% 作为定金（定金 MUST 至少 1 灵石且 MUST 保留至少 1 灵石尾款）；调货时长 MUST 按单价分档在 2~12 小时之间；单价 MUST 由系统定价（在售商品用当前标价，非在售商品用物品基准价的 2 倍），玩家与 LLM MUST NOT 篡改。订单到货 MUST 由玩家交互时的惰性判定驱动，MUST NOT 依赖定时任务。

#### Scenario: 下单调货

- **WHEN** 玩家在掌柜对话中为无货物品下单且灵石足够
- **THEN** 系统扣除总价 10% 的定金并生成等待调货的订单，回复单价、件数、定金与预计到货时间

#### Scenario: 到货惰性判定

- **WHEN** 订单已过约定调货时长后玩家再次经掌柜查询或取货
- **THEN** 订单状态转为「已到货」，可补尾款取货

### Requirement: 调货取货与取消

已到货订单 MUST 可补尾款取货：取货 MUST 原子完成扣尾款与物品入包并置为已取货，并发重复取货 MUST 至多成功一次。取消规则：未到货 MUST 全额退还定金；已到货 MUST NOT 退还定金；已取货或已取消的订单 MUST 拒绝再次操作；订单 MUST 只能在原下单商铺取货或取消。

#### Scenario: 补尾款取货

- **WHEN** 玩家对已到货订单办理取货且灵石足够
- **THEN** 扣除尾款、物品按件数入包、订单置为已取货

#### Scenario: 未到货取消退定金

- **WHEN** 玩家取消仍处于等待调货的订单
- **THEN** 全额退还定金，订单置为已取消

#### Scenario: 到货后取消不退

- **WHEN** 玩家取消已到货的订单
- **THEN** 定金不退还，订单置为已取消

### Requirement: 调货进度查询

掌柜对话 MUST 能查询玩家的调货订单进度：等待调货 MUST 告知预计剩余时间，已到货 MUST 告知需补的尾款；玩家在该商铺存在未结订单时，订单进度 MUST 注入掌柜对话上下文，使掌柜可在对话中主动提及。

#### Scenario: 查询订单进度

- **WHEN** 玩家在掌柜对话中询问调货进度
- **THEN** 回复按订单列出物品、数量与状态，等待中给出剩余时间、已到货给出应补尾款

#### Scenario: 掌柜主动提及

- **WHEN** 玩家与原下单商铺的掌柜对话且存在等待或已到货的订单
- **THEN** 掌柜的对话上下文包含该订单的进度信息

### Requirement: 旅行商人临时商铺

系统 MUST 在「旅行商人」选择事件（`travel_curious_merchant`）中玩家做出选择后就地开摊：摊位 MUST 随机提供 4~6 件带基准价的商品，单价 MUST 由系统按「基础价 × 0.5~3.0」随机定格，库存 1~3；摊位 MUST 在开摊 30 分钟后失效。交易 MUST 经「游商」指令的自然语言对话完成，价格与库存 MUST 由系统裁决，LLM MUST NOT 自行定价；购买 MUST 原子扣灵石、发货并扣减摊位库存，灵石不足或库存不足 MUST 拒绝。

#### Scenario: 事件开摊

- **WHEN** 玩家在旅行商人选择事件中做出选择
- **THEN** 商人就地开摊并提示可在 30 分钟内用「游商」挑拣货物

#### Scenario: 对话购买

- **WHEN** 玩家发送「游商 我要买一份…」且灵石与摊位库存充足
- **THEN** 原子扣除总价、物品入包、摊位库存减少

#### Scenario: 库存不足

- **WHEN** 玩家购买数量超过摊位剩余库存
- **THEN** 拒绝成交并提示剩余库存，灵石与背包不变
